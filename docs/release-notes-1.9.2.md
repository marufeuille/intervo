## Play Console（ユーザー向け・詳細）

### 概要
スマートフォン用アプリで、ウォッチから受信した完了履歴の Health Connect / Bluesky(PDS) への同期を自動化しました。手動の再同期ボタンに頼らず、受信時や設定保存時に自動で同期されます。ウォッチアプリの機能に変更はありません。

### 新機能 / 修正・改善
- **受信時の自動同期** — ウォッチから完了履歴を受信したタイミングで、Health Connect / Bluesky(PDS) への同期を自動で実行するようにしました。これまで一部のケースで必要だった手動の再同期操作が不要になります。
- **設定保存直後の自動同期** — Bluesky(PDS) の設定を保存した直後に、それまで溜まっていた未同期の履歴を自動で送信するようにしました。
- **通信状況に応じた自動再試行** — 通信が一時的に不安定でも、ネットワーク接続が回復したら自動で同期を再試行するようにしました。
- **手動の再同期ボタンは継続** — 即時に反映したい場合のために、これまでの手動の再同期ボタンも引き続き利用できます。

## Internal Notes

### バージョン
- app（Wear）: `versionCode` 109020 / `versionName` 1.9.2 → `wear:internal` トラック
- companion（phone）: `versionCode` 109021 / `versionName` 1.9.2 → `internal` トラック
- semver からの自動採番: `(major*10000 + minor*100 + patch)*10 + offset`（app offset=0 / companion offset=1）。1.9.1（Wear 109010 / phone 109011）より単調増加。

### 主な変更
- **WorkManager による同期の委譲**（PR #52）。受信時・設定保存時の PDS/HC 同期を `SyncWorker` に委譲し、ネットワーク接続を制約に、失敗時は指数バックオフで自動再試行する構成へ変更。連続受信は `REPLACE` で 1 本に畳む。
- **受信処理の信頼性向上**（PR #52）。`WorkoutHistoryListenerService.onDataChanged` で `scope.launch` に投げっぱなしにしていた同期を解消。短命なサービスがメソッドリターン後に破棄されるとネットワーク同期（特に PDS の createSession→putRecord）が完走前にキャンセルされ、履歴は届くのに PDS へ上がらない事象を修正。Room 保存だけ `runBlocking` で確実に完走させ、ネットワーク同期は `scheduleSync()` で Worker に委譲。
- **設定保存後の自動同期**（PR #52）。`SettingsViewModel` で PDS 設定の保存直後に `scheduleSync()` を呼び、設定前に溜まった未同期ぶんを自動送信。設定直後の手動ボタン操作を不要に。
- **無限リトライの抑止**（PR #52）。再試行対象は PDS 設定済みで残っているぶんのみとし、HC 権限未許可による無限リトライを回避。
- 依存追加（PR #52）。`companion/build.gradle.kts` / `gradle/libs.versions.toml` に WorkManager を追加。

### Play 提出時の注意
- **DB の破壊的変更は本リリースには無い**（companion DB スキーマ変更なし）。
- **外部送信の発生条件は 1.9.1 から不変**。PDS への送信は引き続き利用者が URL とハンドル/App Password を設定した場合のみ発生する。本変更は送信の「タイミング/確実性」を改善するもので、送信されるデータの種類・送信先の決定方法は変わらない。公開中のプライバシーポリシーと Play のデータセーフティ申告は 1.9.1 のままで整合する（再申告は不要）。
